## 修改前的证据与问题

1. **作品演示（高优先级）**：首屏手机停在空对话，三个场景必须手动操作；现有八步引导仍要求连续点击。评委没有操作时看不到输入、判断、提醒的完整过程。需要默认自动讲解，随时暂停、重播或切到手动。
2. **图片理解（高优先级）**：图片卡已有保存的 VLM 结论，却把缺少 `promptId` 关联显示成“未关联到同图模型调用”，容易被理解成没做识图。应分别说明“保存结论”和“调用明细”；只按实际 ID 或相同输入字节关联，不能按相邻时间猜测，更不做真人身份关联。
3. **视频向量库（高优先级）**：先展示播放器、索引、关键帧，检索结果位于长页末尾。当前只有私有查询诊断，无法说明问了什么、如何召回、如何复核。应把经过明确公开的真实查询案例放在首屏，保留原片时间定位；其他私有查询继续保护。
4. **深度/光流（高优先级）**：新后端启用 DepthART448、DIS FAST 与守护辅助处理，但采集器仍读取旧字段。运行时首尾分析表和视觉控制表均为 0 条，部署能力不能冒充完成记录。应展示实际配置、运行记录数量、策略/跳过条件及明确标注的已保存录像复算实例。
5. **整体简洁性（中优先级）**：15 个菜单、重复解释、双状态条占用首屏。应保留主要阅读路径，把开发诊断和详细参数折叠。

## 验收原则

自动导览为固定交互脚本，明确标识；真实调用和录像复算另列来源、时间、模型及限制。深度是单帧相对逆深度，不能换算米数；光流只有相邻有效取样且质量检查通过才展示，不作为控制电机的依据。保持 Web 只读、业务鉴权和原有摄像头链路，不把历史录像伪装成实时硬件验收。

## 实施与实测

- 默认 60 秒自动导览，三个场景各五步；可暂停、重播、逐步推进，最后自动打开提醒证据，减少动态效果偏好下默认暂停。保留完整手动 App 体验。六个主要阅读入口常驻，九个开发页面折叠。
- 图像卡分别标明保存结论和调用记录。对 22 条证据与保留的 17 个含图提示词做精确字节匹配，命中为 0；不使用时间相邻或人物外观推测关联。
- 在正在运行的 demo 后端发起两次明确公开的查询，每次召回 3 个候选、尝试复核 2 个；最终文字查询耗时 8.012 秒，图文查询 7.147 秒。豆包视频复核给出的文字案例定位为原片 41 秒、51 秒，图文案例为 37 秒、45 秒。模型描述中的秒数属于候选片段，播放器定位转换为原片时间；页面分别说明。页面标明这是模型判断及估计时间，可以播放核对。
- 实际模型：`doubao-embedding-vision-251215` 与 `doubao-seed-2-1-lite-260915`。视频与关键帧双路余弦排序经 RRF 融合，不把相似度显示成概率。图文查询参考图来自服务端规范化后的实际查询字节。
- 使用已公开 T8171 录像的 44.0 秒与 44.5 秒，调用部署中的 CPU worker 复算：DepthART448 完成，DIS FAST 完成，耗时 1043 ms，前后向一致性 66.95%、几何内点 124、稠密/稀疏运动差异中位数 0.140 px。指标是算法诊断，不是目标动作准确率；没有请求实时画面或控制电机。
- 公开案例由单独维护命令生成，只读采集器不调用模型、不启动任务。仅显式公开案例可读；普通私有搜索、首尾分析正文与身份凭据不会被投影。原片移除或内容变化，相关公开案例退出展示。媒体来源以 SHA-256 校验，失效时显示缺失，不拿其他图片替补。
- 验证：40 项采集器测试、23 项 Web 单元测试、46 项受影响浏览器用例通过（Chromium、Firefox、WebKit、移动 WebKit），生产构建通过。用例覆盖自动/暂停/手动流程、遮挡与基线规则、只读请求、私有查询隔离、图片输入/下载、完整正文、导入导出与溢出。旧测试因菜单折叠、标签简化而更新导航步骤。
