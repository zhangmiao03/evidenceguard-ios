anker 的对话与记忆：调研和下一步设计
核对日期：2026-10-15

结论
我们的定位是“你的安防小助手”：接住日常聊天、解释摄像头事件、记住相关偏好，并在有必要时提醒。已经有 Personal Agent 的执行骨架；主要缺口是聊天到长期记忆的闭环，以及持续对话的上下文整理。无需为了相似的体验更换现有服务端框架或 Doubao 模型。

一、先分清 Muse、OpenMuse 与 Today
1. CopilotKit/OpenMuse 是一个可查源码的独立项目，不能当作 Meta Muse 的官方源码。本次检视提交 1ac68f3909f2478ab6280883f1ab5ea65eb5719d。
   apps/mobile/src/threads.tsx 明确提供 Main chat 和 New side chat；独立话题有各自聊天上下文，保存的记忆共享。docs/RICH-THREADS.md 还说明重命名、归档、恢复和稳定主会话 ID。
   apps/server/src/engine/conversation.ts 的 remember_fact 工具把用户明确提供或确认的偏好写入 memories，记录来源和时间。它的实现不是“每条聊天自动总结入库”，也没有在该工具里完成语义冲突消解：幂等 ID 是请求和文本的哈希，同一事实跨请求重复表达仍需更完整的治理。
   同文件的 delegate_task 将工作交给持久 worker，agent_status 读取实际执行状态；不能只用一句“完成了”替代执行回执。
2. Meta Muse：社区客户端 muse-cli 提供 session-start、主聊天和 side chats，这是支持独立话题的实现证据，但该客户端不是 Meta 官方 SDK。本轮没有登录或实测 Meta Muse 原生界面，不能把社区实现说成官方功能保证。
3. Today：只读检查了本机当前版本，看到固定 miao 对话，以及 Today、任务、记忆和资料面板，未找到新建聊天入口。记忆面板已有分类资料和来源日期。此观察只代表本机版本。
   Today 官方文档介绍可查看、编辑、删除的持久记忆，以及任务执行后更新上下文；没有公开到足以确认其抽取模型、去重算法、存储结构的程度。不能把营销描述补成已经验证的内部架构。

因此，“它们都只能一个聊天”不成立。本轮没有据此删除我们的新建对话入口或旧对话。

二、对我们更合适的交互（建议，尚未实现导航调整）
保留五个入口：助手 / 摄像头 Skill / 任务 / 记忆 / 我的。
助手：默认回到 anker 主对话，接收主动消息；不用让用户为每件小事管理会话。
摄像头 Skill：连接设备、查看事件和配置画面能力。
任务：看执行进度、补充条件、确认启用；在任务内部追问具体结果。
记忆：看 anker 已知的相关偏好、来源与有效期，可纠正、删除。
我的：用户昵称、通知偏好和连接状态；用户身份与 anker 身份分开。

即使最终选择收起“新对话”，后台仍保留任务/事件独立上下文和旧会话。一个默认助手并不意味着把全部消息、全部摄像头记录塞进同一个模型请求。不要清空历史或改变主动提醒的主会话归属。

三、现在的实现，和仍然缺少的部分
已有：
• iOS/Web 的主会话及独立话题，主动消息回到主会话。
• 统一聊天和主动评估运行时；工具范围由宿主代码固定。
• 摄像头事件/图片 → 视觉核验 → 任务与证据回执 → 主动评估 → 去重、免打扰、频率控制 → App 消息/APNs。
• 用户确认的任务草案与启用边界；长任务状态和结果持久化。
• 记忆页手动添加/删除，每个安装身份最多 20 条；可设 24 小时有效期。
• 对话读取相关安装身份已保存的记忆；记忆不增加工具权限。

缺少：
• 聊天自动提出/保存记忆的工具和界面；目前“我家有猫”说完并不会进入记忆页。
• 稳定偏好与临时事实的分类、语义去重、矛盾更新和来源追溯。
• 长会话滚动摘要。当前 recent_context 只在 18000 字符预算内保留最近最多 16 轮，不能当成无限记忆。
• 个人记忆的向量检索。现有 Doubao embedding 主要服务视频证据检索，不代表个人记忆已进入向量库。

四、建议的记忆闭环（设计，尚未接入）
用户消息
  → Doubao 提出候选事实，附本轮 ID、原文依据、类别、有效期
  → 服务端核查来源、安装身份、重复和矛盾
  → 用户明确说“记住”时直接保存并展示回执；隐含偏好先展示可确认的记忆卡
  → 记忆页可查看、修改、删除
  → 后续对话/主动评估只取相关、有效、已确认的记忆

例子：
“我家有只猫” → 候选家庭事实“家里养猫”，确认后保存。
“这周出差” → 先补足结束日期，作为临时上下文；到期不继续当作用户不在家。
“以后别提醒猫经过门口” → 同时涉及偏好和任务规则；保存偏好不等于已改动守护规则，仍需走任务编辑与确认。
“刚才门口有人” → 一次事件，归入事件记录，不写成长期人物身份。
“不是猫，是狗” → 展示替换的旧事实，确认后标记旧版本被取代。

服务端建议增加 memory_candidates 与 memories 的来源/版本字段：client、sourceRunId、sourceSpan、kind、status、expiresAt、supersedesId、revision。候选产生只读，确认写入走明确接口；主动评估仍无记忆写权限。记忆删除后不得因重扫旧聊天又自动恢复。密码、Token、SDK 凭证不进入记忆。
第一阶段总量仍小，先用结构化过滤、归一化去重和版本管理即可；需要扩大容量时再用既有 Doubao embedding，保持 1024 维兼容，不引入新模型供应商。

五、说话方式
首次见面：“我是 anker，你的安防小助手。想看看家里的情况，或有件事需要留意，都可以和我说。”
普通问候：“嗨，我在。”不在每次回复重复岗位介绍。
有实际视觉回执：“这张图里，包裹还在门口。”
仅设备标签：“门铃报了‘有人’，但还没有画面，我没法确认发生了什么。”
草案已保存：“规则整理好了，还没启用。你看看有没有要改的。”
相较于多加拟人词，更重要的是接得上之前的事、少重复、不打扰、准确说明做到了哪一步。单张图片不表示持续监看；APNs 接受请求不等于手机已看到通知。

六、本轮落地范围
已修改 iOS/Web 开场和共享助手定位，保留自然简短的聊天及证据边界。
机器人头像仍需核对正确 IP/原图：找到“安小克”的设计出处，以及不同的 Soundcore 助手 Anka；尚未获取并确认适用于本项目的目标素材。未用通用机器人冒充官方 IP，未改动用户昵称。
尚未实现上述自动记忆闭环或删除新对话入口。未上传、分发 TestFlight，也未部署云端。
