# v0.7：录像回放驱动守护 Skill

这是有限录像的顺序回放测试，不是真机实时守护，也不是可靠性验收通过声明。

## 已实现

- 原生 App：助手生成草案 → 选择已导入录像 → 按录像首帧圈选对象与关注区域 → 确认 → 运行进度 → 提醒 → 视频证据播放。回放输入与合成标记输入在编辑器中明确区分。
- ReplayAdapter 只裁出推进到当前游标的片段，最长 12 秒，蓝框标出关注区域。建立目标在场基线后，逐段判断拿取离区，连续多次一致判断后提醒。每次模型完成后才推进，处理慢时回放变慢。
- 与已有 harness 共用 Skill、设备独占、CameraService、执行代次、运行记录和证据存储。旧任务的迟到结果不能在暂停、切换、断流后生成提醒。历史检索只读已存资料，可并行。
- 有限回放在首次提醒、片尾或 20 次模型观察后结束。连续 3 次模型失败暂停；遮挡/失败不触发拿取提醒。服务重启暂停回放，手动恢复后重建基线。
- 提醒视频仅包含该次已到达窗口，保留原片相对时间；处理时间不冒充拍摄时间。支持 HTTP Range 与原生 AVPlayer 定位。标记已核验保留证据，不重新操作摄像头。

## 实际公开录像测试

来源：[Latch-Video-Package-Theft](https://huggingface.co/datasets/DiricziZsolt/Latch-Video-Package-Theft)。使用之前已导入的样例 A / t4，8.033991 秒。原始拍摄日期未知，未填入虚构日期。数据集页面未提供明确使用许可，原始媒体仍在本机测试目录，不随工程交付。

第一次隔离库实测使用当前配置的 Lite 视频模型：

| 到达原片时间 | 模型与执行器结果 |
|---|---|
| 2 秒 | 看见长纸箱在区域内，建立基线 |
| 3、4、5 秒 | 尚未发现拿取离区，不提醒 |
| 6 秒 | 拿取候选，复核 1/3，动作约 4.7 秒 |
| 7 秒 | 候选 2/3，动作约 5 秒 |
| 8 秒 | 候选 3/3，生成提醒，保存 0–8 秒证据，定位约 5 秒 |

7 次模型观察共约 35 秒，尚不满足低延迟实时监控指标。详细回执见 `replay-validation-v07.json`。这几次判断使用重叠窗口，并非独立证据或独立模型投票，不能据此推算误报概率。人工粗标注动作范围 4.5–5.5 秒，本次定位落在范围内。

## 修复与失败追踪

增加每次请求的 HTTP 状态、耗时、结束原因和结构校验错误，私有密钥不进入日志。此前仅记录 ProviderError，不能回溯断言旧失败全部来自模型。

新增诊断重现一个确定的程序问题：原片实际时长 29.581995 秒，提示词舍入为 29.582，模型按提示词返回尾点后，被严格校验误拒绝。现在提示词保留 9 位小数，仅对终点超出不超过 1 毫秒的报告量化误差做有日志的调整；更大的越界仍拒绝。回归测试覆盖这两种边界。

修复后的四个问题各一次复测：三个有效结果均符合粗标注，遮挡样例 o1 不再因尾点舍入失败；拿取正例该次请求遭 HTTP 429，明确记为失败，不计入通过。其后/另路的顺序回放拿取正例成功，不能以成功结果抹掉 429 记录。参见 `video-diagnostics-v07.json`、`video-regression-v07.json`。

## SDK 边界

T8171 / T8214 正式 SDK 仍待主办方提供。保留 `OfficialSDKBridge` 的设备握手、截图、会话起停、历史导出，并新增接收时间受限的 `read_session_window` 预留合同：设备/通道/会话/执行代次、原始采集时间、接收时间、时钟不确定度、受控媒体路径。尚未调用这个预留入口。

当前 ReplayWorker 接收的是 ReplayAdapter 的本地录像窗口。正式 SDK 到手后，需要实现会话媒体入库及窗口适配，验证停止回执、断流、时钟和能力；不能直接打开 capability 开关就宣称完成真机接入。详见 `../Cloud/CAMERA-SDK-CONTRACT.md`。

## 尚缺的验收

- 同一段连续的“放下 → 等待 → 拿走”视频；当前正例开头包裹已在场。
- 单纯经过、区内移动、夜间、逆光及遮挡解除等独立反例，跨模型重复与人工全文复核。
- 真机延迟与功耗、后台推送、多进程设备协调、部署鉴权。
- 本轮只对“物品拿取离区”执行回放，其他 Skill 不能据此视为可运行。

## 本机原生 App 联调结果

iPhone 17 Pro 模拟器中实际完成：输入需求并发送 → 云端助手调用工具生成草案 → 点击草案 → 选择公开录像 A → 保存 → 确认及同设备冲突切换提示 → 运行结束出现提醒 → 任务证据 → AVPlayer 播放触发片段。为保证使用相同标注区域，本轮精确 ROI 由开发接口写入草案，再在 App 首帧中人工检查；未把这一步声称为全程手势圈选验收。编辑器另增加可输入的坐标数值，保留滑杆与拖动。

第二轮由 App 启动，7 次模型观察，到达第 8 秒后生成提醒，模型时间 4.8 秒；完整回执见 `native-replay-v07.json`，播放截图见 `replay-playback-v07.png`。完成测试后已恢复原有“双摄像头联调守护”模拟任务，保留回放任务和视频证据供查看。

服务端自动化 69 项通过（包括暂停/切换/断流迟到结果拦截、基线重建、真实 FFmpeg 截止帧、播放 Range、任务独占、确认与核验）；Xcode iOS Simulator 构建成功。自动化大多数使用桩模型，真实模型效果仅以以上单独记录为准。
