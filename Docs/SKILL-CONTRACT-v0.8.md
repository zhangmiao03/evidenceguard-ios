# v0.8：执行能力合同与启用前试跑

本轮围绕 Skill 完善创建、校验、试跑及核验，复用已有 harness 与回放引擎。没有新增宠物识别能力，也没有整体迁移 MiiMiao。

## 用户流程

1. 向助手描述任务。助手查询能力目录；创建工具在保存之前再执行后端能力检查，模型无法省略这一检查。
2. 草案明确任务类型及持续秒数需求。包裹拿取、测试标记、宠物、车辆、自定义和未明确类型分别处理。未知规则参数会被拒绝，不悄悄丢弃。
3. App 展示后端生成的执行合同：前置状态、触发条件、连续观察语义、无法确认处理、证据与结束条件。自由文字是需求说明，不会自动变成可执行逻辑。
4. 包裹任务选取已存录像，核对目标与区域，点击“保存并试跑当前草案”。试跑只读录像，不占用摄像头，不暂停已有守护，也不写正式告警或生产证据。
5. 查看逐段报告及可播放片段。成功完成且建立过清晰基线、无输入/模型失败后，才可以勾选已核验并继续确认。
6. 正式启用回放仍需独立的录像测试确认和摄像头占用检查。试跑成功不会自动启用，模型也没有启用权限。

## 能力边界

| 类型 | 当前能力 |
|---|---|
| 包裹拿取离区 | 仅 2–60 秒已存录像回放；单录像绑定摄像头，先建立在场基线，直接看见拿取离区，连续 2–5 次模型观察，一次性并保存证据 |
| 测试标记区域进出 | 仅就绪的 fixture-lab 合成测试源；不能冒充真实物体识别 |
| 宠物、车辆、自定义行为 | 可保留需求，不能启用 |
| 未明确任务类型 | 必须补全，旧草案不会自动归为包裹任务 |
| 持续 N 秒 | 参数保留但启用受阻；不以连续 N 次偷换时间语义 |

“可执行”是当前已实现能力的合同校验，不证明视觉模型一定理解正确。自然语言到任务类型仍由模型提议，需要用户核对。已有已确认任务继续按旧配置运行；新建/修改草案启用时采用新校验。

## harness 改动

- 新增服务端能力目录与确定性的合同检查。创建后的说明基于工具回执生成，避免模型额外声称不支持的能力以后可以直接启用。
- 试跑使用同一个 ReplayWorker，但在临时隔离数据库执行；输入只经本地 ReplayAdapter，不进入设备命令或任务占用通道。
- 报告持久化，包含逐段结果、基线、失败数、是否会提醒、模型时间、实际观察覆盖范围、耗时及视频片段。它不是经过标注的准确率报告。
- 报告绑定 Skill ID、版本、对象/区域/规则/来源配置、原片摘要、模型地址与 ID、合同版本。修改后过期，不可用于启用；进行中的试跑遇到修改停止并丢弃迟到结果。
- 最多两个试跑请求在队列中，一个试跑执行；共用历史视频复核并发门，每次沿用回放观察上限，整体 6 分钟超时。可取消，服务重启标记中断，不伪造继续成功。
- 启用时检查指定报告是否属于当前草案并已核验，记录报告 ID。设备占用冲突照常处理。
- App 保留未保存修改，往返报告页不会把它们误认为已保存。正式告警与试跑报告分开显示。

尚未完成：统一管理所有模型调用的限流退避/Token 成本、分布式队列、通用断点续跑、SSE、正式摄像头 SDK 与后台通知。这一轮没有将其宣称为已完成。

## 实际验证（2026-09-23）

- 真实助手调用了 `list_skill_capabilities` → `draft_visual_skill`，生成 `parcel_removal`、0 秒时长要求、3 次观察、一次性、保留证据的草案。
- 复用此前公开样例 A，首帧的精确对象/区域由开发接口写入，再在原生 App 查看与发起试跑；这不是全程触摸圈选验收。
- App 发起试跑：7 次真实模型观察，耗时 36.25 秒，原片约 4.8 秒拿取，观察推进至 8 秒。第 5 秒片段为无法确认，后续 6、7、8 秒连续判断形成候选提醒。
- 试跑结束后任务仍为 draft；对应正式证据为 0；原“双摄像头联调守护”持续运行。
- 原生 App 展示报告并用 AVPlayer 播放试跑片段。未核验时启用禁用，核验后可继续；启用请求触发设备占用确认，测试选择保留草案，未切换原任务。
- 真实助手针对宠物60秒不动的需求保留了 `pet_activity` 与 `durationSeconds=60`。服务端确认接口返回 409、不允许启用。首次自由生成回复错误暗示未来可直接启用，随后改为确定性的回执说明，并增加针对错误模型承诺的回归测试。首次回复保留在诊断文件，不覆盖历史。
- 服务端 78 项检查通过，涵盖能力拒绝、时间要求保留、报告归属/版本/模型变化失效、试跑隔离、取消、重启、无基线与失败不通过，以及已有回放/历史/设备独占路径。Xcode Simulator 构建通过。

真实模型仅测试以上特定样例，不能据此估计误报率。仍缺连续“放下→等待→拿走”和独立负例集；未将报告里“未触发”解释为不存在风险。
