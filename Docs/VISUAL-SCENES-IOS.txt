EvidenceGuard：iOS 自定义视觉场景第一版
2026-10-16

范围
以 Visual Skill 系统设计方案 v1.1 的“一句话 → 画面框选 → 确认开启”为主线。
新入口在“摄像头 Skill / 自定义场景”，同一列表也显示在“任务”。
这不是通用代码 Skill、Web 管理台或 HTTP 插件平台。旧录像回放、标记任务和原始记录保留。
普通助手聊天仍沿用已有工具；这批自然语言创建与修改走新的 iOS 场景编辑页，不宣称已替换所有旧对话创建入口。

1. EvidenceGuard/VisualSceneView.swift：三步创建、已保存草稿恢复、同一草稿补充条件、冻结画面、触摸框选、确认、暂停、证据入口。
   框选支持拖动和依次点两个对角。独立模拟器已实测两个对角点路径；build 14 真机已实测拖动框选成功。
2. EvidenceGuard/APIClient.swift：复用原访问鉴权、安装身份和媒体鉴权；新增 visual-scenes API。
3. EvidenceGuard/SkillsView.swift：只插入两处新模块入口，不替换主线程正在修复的官方设备/事件/任务部分。
4. Cloud/server/evidenceguard/visual_skills：独立 schema、harness 适配、持久化与状态机、API。
5. Cloud/server/evidenceguard/app.py：注册服务、路由与生命周期，沿用原 personal_client 身份证明。
6. EvidenceGuard.xcodeproj/project.pbxproj：新 Swift 文件加入两个既有 App target。

Harness 分工与 miimiao 借鉴
实际阅读 MiiMiao/backend/core/workspace/harness.py、integrations/codex/context_handoff.py、skill_adapter.py、core/skill_forge.py。
采用其“模块自己管理输入和验证，通过窄接口调用既有 Harness”的设计，不复制代码、依赖、供应商、账号或收费配置。
借鉴三点：
- 模块工具范围由宿主确定，不依赖自由聊天选了哪些工具。
- 后续修改带上真实完整草稿和用户原话，保留没有修改的条件。
- 草稿、确认版本、执行观察与回执分开，模型回复不能作为已经开启的证据。

EvidenceGuard 的 SceneHarness 使用当前 Agent 的 executor 选择。
codex-app-server-v1：复用当前 CodexTurn、同一 Doubao 配置和并发 gate，结构化输出，不提供硬件或启用工具。
bounded-chat-v1：复用当前模型 provider。实际视觉判断复用已配置的 Doubao 视觉模型及自动视觉额度。
保留既有 Codex 主聊天、硬件确认及 SDK 通道；不从 MiiMiao 引入另一套模型供应商。

能力范围与真实含义
- 首版为固定视角内对象/类别进入或离开区域，单次或持续提醒。
- 特定物体模式：框出物体，同时把初始位置作为关注区域；类别模式：框关注区域，对象由文字指定。
- 每次至少两个有效采样，确认跨度 15–600 秒；这是采样跨度，不证明中间每一秒都满足。
- 先建立触发前基线，再判断变化。初始就没有目标、黑屏、遮挡、断流、过长间隔不直接产生“离开”提醒。
- 同一帧不能重复累计；视角/直播会话变化要求重新框选。暂停清除旧框选和不完整证据。
- 新场景每台摄像头同时只开启一项，既有任务占用优先，不抢占设备或控制摄像头。
- 只允许新鲜 official_live_ios 画面，事件缩略图、录像回放、Web 和合成来源不能用来启用这个新入口。
- 仍依赖 App 前台直播会话，锁屏后不能承诺持续观察。沿用已有自动视觉额度，额度耗尽时明确未知。
- 身份识别、声音、主观行为、定时时段、多条件组合、云台跟随等未接入，不让模型自行生成执行代码。
- 提醒原子保存到证据、助手主时间线和收件记录，推送复用原 outbox 与用户开关/免打扰/频控。

一致性和保全
visual_scenes 新表按安装身份隔离，原 Skill 数据表不迁移。
创建请求按安装身份与 requestId 幂等，修改/框选/启用检查 revision；异步返回核对版本，暂停后旧观察不能发消息。
模型生成中重启可恢复原话，不自动启用。主动观察重启清掉部分基线，不拼接跨重启证据。
模型原始校验异常不展示到产品界面。
主工作区已有修改保留，没有 reset、clean、删除原项目文件或提交他人的未完成修改。build 14 基于另一任务已提交的 1ba73c5 加入本模块。
