# EvidenceGuard / 官方 SDK 工作区切换

日期：2026-10-14。分支：`dongrunze`。

## 目的与实现

团队可以在同一个 iOS App 或 Web 工作台中，快速切换到赛事交付的原版 Demo，先确认账号、硬件和 SDK 能力，再回到 EvidenceGuard 检查业务链路。

这里的“版本切换”是**工作区和运行会话切换**。不会在运行时下载不同版本的原生框架，也不会修改设备固件。两种界面使用本机恢复的同一份官方 SDK；Web 原版的 SHA-256 和运行时版本会显示在工作区，便于团队对照。

| 端 | 本项目工作区 | 官方工作区入口 | 实际加载内容 |
| --- | --- | --- | --- |
| iOS | SwiftUI、设备同步、直播取帧和 Agent | 顶部“切换官方 SDK”；我的 → 官方摄像头接入也有入口 | 官方 `SampleApp()`，与 `Main.kt/MainViewController()` 使用同一根界面；保留完整 Compose 导航 |
| Web | React 设备工作台、直播、Agent、证据 | 页面顶部“切换至官方 SDK” | 独立 iframe 内的官方 `App/AuthForm/LivePanel/AIRawFramePanel`，原始 UI 文件不重写 |

本轮不开发 Android App；官方 Common 导航中的功能可作为 Android 对照材料，不代表 Android 客户端已加入本仓库。

## iOS 操作

1. 持有官方资料包的 Mac 执行 SDK 恢复和 **重新运行 `python3 SDK/prepare.py`**；本次修改了 Kotlin 桥接，旧 SampleCore 不能代替新产物。
2. 打开 `EvidenceGuard.xcworkspace`，选择 `EvidenceGuardSDK` 真机方案构建。普通 `EvidenceGuard` / Simulator 会显示构建条件与指引，不假装已经加载官方页面。
3. 点顶部“切换官方 SDK”，等待本项目直播、取帧和云端采集会话结束。
4. 在官方 Business 登录表单核对账号、Token 与 PR/QA，再进入官方添加设备、设备列表、直播、事件、设置等页面。原版登录表单采用原版缓存；不会把本项目 Keychain 凭证静默复制进去。
5. 官方模式顶部始终保留“返回本项目”和检查指引。返回时退出 Compose 内容、释放播放器/订阅、注销官方登录上下文，再打开本项目“官方摄像头接入”。**重新查询设备并同步，然后手动开流**。

原版的设备配置确实作用于硬件：绑定、解绑、Wi-Fi、画质、检测规则、通知、存储设置等不会随工作区切换撤销。产品模式保留自己的 Keychain 配置和云端数据，但不自动采用原版表单里另一个账号。新增相册权限说明、对讲麦克风说明及官方全屏方向的系统适配；手机仍需实际授权。

## Web 恢复与启动

在仓库根目录：

```bash
python3 scripts/import_web_sdk.py "/资料包/demo工程/WebSDKDemo/public/sdk"
python3 scripts/import_official_web_demo.py "/资料包/demo工程/WebSDKDemo"
cd Web
npm ci
npm run build:official
npm run dev
```

Windows 将 `python3` 换成可用的 Python 命令。后端仍按根 README 监听本机 8790。`build:official` 生成 `Web/public/official-demo`；此后 `npm run build` 会把它和 `/sdk` 一并复制到 `Web/dist`。生产环境设置 `EG_WEB_ROOT` 指向该 dist，并使用 HTTPS 与团队鉴权。**只执行普通 `npm run build` 不会凭空获得官方 Demo**；缺少原文件时显示恢复命令。

- 原始源码、UMD、构建产物都被 Git 忽略；团队成员各自从主办方资料包恢复。
- 导入脚本只复制 `.ts/.tsx/.css`，拒绝带非空鉴权默认值的配置，不导入 `.env`。
- `manifest.json` 记录原始源码散列、SDK 散列及明确的适配项。
- 原版界面文件保持原样；仅将 `config.ts` 的 localStorage 凭证保存改为 iframe 内存保存，增加同源鉴权代理和生命周期外壳。刷新/退出后原版凭证不在本项目 Web 存储中保留。
- 若本项目已有 Web 参数，会作为原版表单的**未提交默认值**带入，仍需点击原版连接按钮。团队令牌不放进地址栏；只发送给同源且与当前 iframe 匹配的窗口。
- 页面“结束官方会话”及“返回 EvidenceGuard”都会卸载原版播放器。浏览器切到后台时也结束官方会话；返回前台需重新打开。

### 官方 Web AI 面板

原版 `AIRawFramePanel` 的按钮会采集 10 帧并自动提交官方 Nova Pro 网关。本项目 Agent 不接收这批帧。服务端需设置：

```dotenv
EG_OFFICIAL_AI_KEY=主办方发放的模型网关密钥
```

密钥仅在后端环境中，不能写入 Web 的 Vite 环境变量。新增代理固定指向官方 `https://ai-router-cn-pub.anker-in.com/chat/completions`，只允许 `hackathon/v_model/nova-pro`、一个 user 消息、1–10 张内联图片和一段文字；上限 20 MB。不接受远程图片 URL、工具调用或任意目标地址。没有配置时返回明确的 503，不能把它记录为设备取帧失败。

原版 UMD 及 Demo 使用的依赖不等同于已经过本项目完整安全审计。官方鉴权辅助依赖 `elliptic 6.6.1` 的 npm 审计仍有一项 low 告警、无直接修复版本；保留它用于原版协议对照。自有业务工作区继续用 WebCrypto。SDK 内部可能有调试日志，勿将含凭证的浏览器控制台或原版日志上传公共仓库。

## 两端检查范围：按实际入口核验

“有入口”与“设备声明支持”“实机通过”是三层不同结果。下面是检查导航，不是成功承诺。设备设置里部分项由 Thing Model、固件与实际设备属性决定是否显示。

| 检查组 | T8171 云台摄像头 | T8214 门铃 | iOS 原版入口 / Web 现状 |
| --- | --- | --- | --- |
| 账号与设备 | 正确账号能发现目标 SN，重复登录、账号切换 | 同左 | iOS Business/设备列表；Web 鉴权表单 + 手工 SN |
| 首次添加与绑定 | 按该型号的官方步骤配网、绑定；重试/错误密码 | 门铃对应的官方添加流程 | iOS 添加设备。此版 Web Demo 没有完整添加导航 |
| 配网路径 | 逐项记录二维码/热点/蓝牙是否实际进入、哪些只是通用代码 | 同左，不能由 T8171 推断 | 以型号注册流程为准；不能将通用 BLE API 当作两款设备均支持的结论 |
| 网络条件 | 同网、手机流量/电脑异网、设备断网、休眠唤醒 | 同左 | 两端原版直播逐项测试；一次成功不能推断始终跨网可用 |
| 直播画面 | 首帧耗时、清晰度、有效帧、持续时长、断流恢复 | 首帧、主副镜头/布局、断流恢复 | iOS Live；Web DeviceLiveLayout/重连 |
| 声音与对讲 | 收听/静音、麦克风/扬声器设置、开始/停止对讲 | 同左，另测门铃呼叫、快捷回复 | iOS Live/Audio/Response。Web 只记录当前工具栏实际露出的项 |
| 云台 | 各方向、停止、预置位、巡航、追踪及恢复 | 不按云台验收 | iOS Live/PTZ Settings/Presets/Cruise；Web 缺少页面的项转原生核验 |

| 历史记录 | 事件列表、事件片段、下载、无记录与过期 | 同左，门铃/包裹相关事件另外记录 | iOS Events / EventPlay / Download；此版 Web Demo 不提供同等历史导航 |
| 检测与通知 | 移动/声音检测、灵敏度、区域、通知开关 | 门铃响铃、室内响铃、包裹/移动检测 | iOS Motion / Sound / Notification / IndoorChime |
| 画面配置 | 视频与录像画质、夜视、灯光、水印、隐私区 | 逐项看能力表是否提供 | iOS Video Settings；Web 没有完整设置列表 |
| 电源与存储 | 休眠/唤醒、电量、录像策略、本地存储信息 | 同左 | iOS Power / LocalStorage。断网是否录像、恢复后何时同步需用实机时间线核验 |
| 通用设置 | 名称、Wi-Fi 状态/更换、时区、设备信息、OTA | 同左 | iOS General；原版提供的入口不代表每个操作都应自动执行 |
| 多设备与多端 | 同账号两台设备、两个客户端同设备、不同账号分享 | 同左 | iOS 设备列表/ShareDevice + Web 连接对照，记录占用/抢流结果 |
| 高级物模型 | 能力声明、属性读写、动作参数和事件回执 | 同左，勿照搬 T8171 的标识符 | iOS DeviceCapability / ThingTest。声明支持仍需实际回执验证 |
| 回到业务模式 | 重新查设备 → 同步 → 直播 → Agent 新画面 | 同左 | 本项目工作区完成；不自动重启旧会话 |

Web 的“硬件检查记录”支持按型号和手填 SN 标记未测试/通过/失败/设备不支持/转原生检查，并导出 JSON。它是测试人员的手动记录，不是 SDK 返回的自动能力证明；切换工作区前导出，刷新不会保留未导出记录。请填写网络、固件和现象，勿写密码或 Token。导出的 SN 是人工填写，需和原版连接页核对。

## 会话与接口边界

### 从本项目进入官方模式

停止客户端播放器、取消帧订阅/轮询，等候尚未结束的 start 请求，向 Cloud 停止本安装的采集会话。如果停止请求失败，则等候 12 秒租约 TTL 再留 1 秒余量，然后进入官方界面。原版不获取本项目采集租约，也不响应 Agent 的取帧命令。**同一设备如果仍被另一部手机、另一浏览器或其他 App 使用，工作区切换不能强制停止那个外部客户端**；团队应先停掉它以做单端基线测试。

### 从官方模式返回

- Web：精确校验 `postMessage` 来源窗口、同源地址与当前随机会话通道；卸载原版 React、取消请求和订阅，等待原版文档使用的释放余量。若子页面无回执，移除 iframe 终止该浏览上下文后才返回。
- iOS：将官方 `SampleApp` 从 Compose 内容移除，让原版 Live/Event/PTZ/Download 的 dispose 路径运行，清理官方全屏监听和共享 controller 引用，然后清除当前账号会话；产品再次初始化自己的 SDK 参数。
- 默认返回停流状态，不以缓存帧冒充实时输入，也不自动重新绑定/解绑/改设备属性。

Cloud 增量只包括官方 Demo AI 固定代理，以及 `/official-demo/` 静态文件访问白名单。页面壳可加载不代表 API 无鉴权；官方 OpenAPI 仍需 `X-EG-Access-Token`，AI 代理需本项目团队 Bearer。没有新增任意 URL 转发器。

## 本轮验证与待验收

本轮本地 Cloud 回归 **163 项通过**，Web **4 项通过**；已构建原版 Web Demo 与本项目 Web。浏览器确认原始鉴权表单可加载、返回可卸载原版页面、检查记录能下载；375 CSS px 的外层工作区没有横向溢出。自动检查覆盖来源导入、代理鉴权/输入约束和跨页面来源校验。最终 CI 结果以本次提交的 Checks 为准。

本机没有 Xcode/iPhone 硬件。普通 iOS Simulator 的 CI 编译不包含 arm64 官方桥接；本次 Kotlin/Compose 桥接必须在持有 SDK 的 Mac 上重新构建。仍需实机执行：

1. 产品无直播 → 官方登录 → 添加/绑定 → 返回 → 重新查设备。
2. 产品正在取流或正等待首帧 → 进入官方 → 官方可独立开流。
3. 官方正在直播、对讲、录像、回放/下载、云台页面 → 返回 → 确认声音/播放/订阅停止。
4. 快速来回切换、断网、锁屏、权限拒绝、账号与 PR/QA 改动后返回。
5. 两款设备分别记录所有可见检查项及物模型回执，不把 Web 缺少入口记录为硬件不支持。
