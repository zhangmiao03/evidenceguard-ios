人员需求修复
“不要让视频里的人离开”被拒绝，是 Skill 需求编译规则把画面中的目标误当成实名身份识别。当前支持人作为可见目标：框选画面中的人，离开关注区域时提醒；也支持有人进入/离开框选区域。前者只在同一固定视角内按选框、位置和可见外观匹配；遮挡、多人相似或目标重入后无法确认时为 unknown。没有接入认出张三、屋主身份或跨摄像头认人的能力。“不要让人离开”生成提醒草稿，不执行阻止人离开的控制。仍需用户框选和确认开启。
已通过线上官方 Codex App Server + 豆包实际生成测试：原句正确生成 object/leaves；“有人进入门口区域时提醒我”正确生成 region/enters；明确识别张三身份仍正确说明未接入。三项均通过。人员规则已经部署；本轮未替用户开启人物守护，也未验收实际人员进出触发的提醒。

摄像头与设备
页面以用途、已确认条件、最近检查结果为主。前端不展示持续直播视频；原生 SDK 渲染器保留在不透明界面之后，为助手和 Skill 提供新画面。App 保持前台时跨栏目维护连接。实际试验确认厂商播放器不能可靠同时解码两台，因此只保留一路；用户或助手可以切换目标摄像头，切换会短暂重新建流，不承诺两路不断流。锁屏或退到后台暂停，不能称为云端全天监控。
真实物理验收：隐藏画面时取得 T8214 新帧；助手请求另一台 T8171 后自动串行切换，18.15 秒取得对应新帧，未混入旧摄像头画面。随后实际助手执行链取得本轮请求后的 official_live_ios 新帧，并用豆包描述了画面中戴眼镜的人、手机和桌面。此轮执行使用独立测试对话，没有代写用户主对话。此前主对话 UI 发送失败输入保留；不能将独立执行链通过写成该 UI 流程已复验通过。
摄像头结果区分最近检查通过、需要关注、正在确认、无法确认等，不把“连接上”当作守护通过；视角变化需要重选，断流前后的采样不拼成连续证据。持续无法确认超过 120 秒时按现有通知偏好发送一次主对话提醒，恢复后可重置；未伪造实体异常或推送验收。
主动触发对用户只用定时、事件、用户指令、特殊（门铃等）四类解释。这不是承诺已实现任意定时、多条件或硬件协议。
中间栏目改为设备，真实 Core Bluetooth 扫描、选择连接、断开和保存设备，标准电量服务可读取电量。真机扫描看到附近 MacBook Pro；没有已验证的安克蓝牙外设连接或除草机等厂商控制协议。原任务数据仍保留，入口转入摄像头页。
