# 官方摄像头事件

2026-10-14：手机流程改为官方摄像头事件，原合成场景不再作为正常入口。用户目前尚未拿到摄像头和赛事账号；以下是代码接入与自动检查结果，真实设备验收尚未完成。

## 使用流程

「摄像头 Skill → 连接摄像头」填写主办方 User ID / Token，选择对应 PR / QA 环境，检查账号下的 T8171 / T8214。凭证只存在本机 Keychain，不发送给 Cloud 或模型。

发现设备后，只将设备身份同步到当前手机服务。在摄像头首页开启「App 打开时同步新事件」，SDK 按设备查询近期事件，上传事件元数据与对应缩略图；切换到其他页面继续，锁屏和 App 不活跃时暂停。设置绑定当前 Cloud HTTPS 来源，不能把一个环境的自动同步开关直接用于另一个环境。

事件出现于摄像头首页；可查看设备事件时间、检测类型、图片分析和证据。助手可用只读 `list_camera_events` 查询新事件，再按需查看已保存图片。新的近期事件完成图片分析后，进入已有价值评分、免打扰、去重和频率策略，通过后产生应用内提醒和 APNs。历史导入不会冒充新事件；检测类型只是 SDK 标签，图片核验也不代表已确认连续动作。

## 官方 SDK 依据

本机恢复的 ESIotKit 2.2.7 官方示例使用 `MegaEventManager.query` / `EventCondition` 查询事件，使用 `MegaEventManager.getEventImageBase64` 读取事件图片。`MegaEventViewModel.kt` 演示事件查询及 `queryFlow`；`EventListComponent.kt` 展示 `DetectionType` 的人物、车辆、宠物、包裹、门铃等映射。

自有桥接在 `SDK/Bridge/EvidenceGuardSDKBridge.kt`，复用上述官方接口；没有改动厂商 SDK 或伪造事件。`queryFlow` 是原生会话内的查询流程，当前没有将其当作服务器 Webhook 或 iPhone 锁屏后的持续监听承诺。

## Cloud 来源隔离

手机服务设置 `EG_CAMERA_SOURCE=official_sdk`、`EG_ENABLE_SYNTHETIC_DEMO=0`，使用 `SDKEventsAdapter` 读取手机中继缓存。没有设备登记时摄像头列表为空，不生成 cam-a / cam-b 占位设备，也不回退到 fixture-lab。

- `POST /api/sdk/devices`：登记 SDK 发现的设备身份；需要原服务鉴权和安装 ID，不接收 SDK Token。
- `POST /api/sdk/events`：原有幂等批量接入，最多 10 条 / 批，图片单独上传；仅允许 T8171 / T8214。
- `GET /api/sdk/events`：最多 100 条，按设备事件时间排序，支持 `cameraId` 筛选，返回截断与持续覆盖状态。
- `/api/bootstrap`：包含正式来源的设备、事件、证据与任务；旧测试数据库记录仍保留。

正常手机工具查询和每日概况排除测试任务、合成证据及回放录像，已挂起的合成提醒不再发布。团队与 Apple 审核环境保持原源码、数据和凭证隔离。fixture-lab 与合成场景仍用于隔离回归，不作为正式摄像头来源。

只登记事件来源时，设备能力仍明确为事件中继。集成同事的直播接入后，同一 SN 使用相同稳定 ID，事件与直播设备合为一条；在 iOS/Web 前台打开直播并收到近期媒体心跳后，才声明新画面取样可用。Agent 请求需要服务器挑战、后续 SDK 媒体活动和对应会话回传，不能用事件缩略图回答新画面请求。直播停止或过期后收回可用状态。设备控制和 SDK 后台事件推送仍未开放。缓存图片不填“新鲜采集时间”，不能显示为实时画面。只有确实选入图片分析的证据才显示分析完成，其余元数据记录不会继承同组其他图片的完成状态。

## 验证与边界

165 项 Cloud 测试通过，涵盖登记鉴权、无设备空状态、来源切换、事件幂等、设备筛选、时间排序、100 条上限和未选图片状态；6 项已有 Swift 契约检查通过，Simulator 编译通过。build 9 已完成签名归档，App 标识、新加坡地址、APNs 配置和归档签名已核对，分发签名及生产推送 entitlement 在导出后核对。build 9 的 SDK 原生桥接未修改；对该归档的私有副本去除签名后，SampleCore 与 build 8 的 SHA-256 一致，UUID 为 `4F781F23-B6CC-303B-B6E1-5F297979DCCB`。分发状态以 [TestFlight](TESTFLIGHT.md) 为准。

当前每 30 秒查询最近 120 秒，单次 SDK 返回最多 50 条、图片最多上传 10 张；高频事件、锁屏时间及未同步时段可能存在缺口。`hasVideo` 只代表 SDK 报告有录像，本轮没有把它冒充可下载、播放的原片。未来需要独立接入 SDK 录像导出或经过验证的服务器事件来源，才能扩展这些能力。

拿到设备后的验收：填入账号 → 发现设备 → 完成一次经过或按门铃 → 对照官方事件时间和图片 → 同步到 Cloud → 查看图片分析与事件页面 → 开启需要的提醒偏好 → 对照实际推送与点开目标。这个步骤不能由模拟器或伪造测试事件替代。
