## 可以演示的闭环

1. 选择包裹、室内宠物、工作室物品场景，说出需求。
2. 生成固定模板草稿，获取参考画面，拖动或点击两个对角框选；没有新画面或选框不能确认。
3. 查看条件后“确认并开启”。调整条件会重新要求画面和选框。
4. 右侧脚本按钮推进检查。未建立基线就触发变化，以及遮挡、断流，一律无法确认。遮挡后需要重新建立基线。
5. 有有效基线后触发变化，生成示例提醒、证据入口，进入 anker 主对话继续追问。
6. 暂停清除旧画面与选框；同一示例摄像头不能同时运行两个守护。两种 T8171 场景共享同一设备约束。
7. 历史对话只演示已保存资料查询，工具菜单不提供实时画面和守护修改。先前消息的画面状态固定，不随右侧脚本变化。
8. 参考图片可框选查询目标；原片页明确没有真实录像文件。此处不上传个人素材。

## 数据与硬件边界

`useIOSTour.ts` 只使用 React 内存状态；不导入业务 API、SDK、Web Bluetooth、麦克风或推送权限。所有网络写请求在回归测试中断言为零。网页刷新清空演示内容，临时记忆的 24 小时只是原生流程说明，不伪装成网页持久化。

摄像头配网、绑定、云台、对讲、取流及设备录像功能依赖手机 App 官方 SDK。单路前台摄像头连接与后台暂停取样的限制在演示中明示。设计素材不代表实时画面或模型识别证据；同一参考照片可用于讲解不同脚本状态。

真实运行数据仍来自 Dashboard 的图片台账、历史回复、提示词、模型、工具、Trace、向量和服务器页面。演示不会把固定回复写入真实台账，不触发真实模型任务，不声称完成原生 Simulator 或硬件验收。

## 实现位置与维护

- `Web/src/dashboard/IOSPreview.tsx`：原生样式页面与子路由。
- `useIOSTour.ts`：演示状态和有效性检查。
- `tourData.ts`：场景、设备和标签定义。
- `Showcase.tsx`：评委引导和状态检查面板。
- `phone.css`：与 Dashboard 暗色样式隔离的手机样式。
- `Web/tests/browser/ios-tour.spec.ts`：真实浏览器点击路径与禁止业务写请求检查。

更新时先核对原生 `RootView`、具体页面及状态约束，再更新上述映射，不恢复旧版首页或全局 SDK 切换。修改展示素材会同时进入在线网站和可下载 ZIP。原生头像使双份资源打包超过旧 2 MB 上限，受校验的发布传输上限调至 5 MB，保留分片和完整 SHA-256 校验。

此次只发布前端资源与网站 ZIP。保留当前采集器和业务后端运行版本，只更新 Dashboard HTTP 服务的 `EG_DASHBOARD_WEB` 路径并重启此只读展示进程。发布前后对照三个业务服务和采集器 PID，核对匿名数据、HTML、资源及 ZIP。备份原 service 文件；失败时恢复同一文件并重启 Dashboard。后续完整部署仍由 `activate.py` 写入新的统一服务配置。
