# Visual Skill 与 MiiMiao Harness 实施检查

这是 v0.3 改造前的检查记录；已落实部分与当前边界请以 [最新实现与验收](SKILL-RUNTIME-v0.3.md) 为准。

检查时间：2026-09-22。依据：团队《Visual Skill 系统设计方案》、本地 MiiMiao v1.0 对照提交 `fe43a78`、当前 EvidenceGuard 源码。

## 结论

保留“一句话 + 圈选 → 草案 → 确认 → 持续观察 → 结果与证据”的主流程。原方案可以作为产品方向，但示例 Schema 和伪代码尚不能直接作为可执行引擎规范。优先做一个完整的物品区域守护 Skill，宠物、车辆等复用基础设施后再扩展。

## 实施前需要修正

| 问题 | 为什么影响 demo | 实施口径 |
| --- | --- | --- |
| 第 3、6 页把目标离开、告警处理与任务完成关联 | 持续守护报警后就停止，无法继续观察恢复 | 分开 lifecycle、observation result、alert；只有一次性任务命中才完成，持续任务继续运行 |
| 一个 ROI 配多台设备 | 不同视角像素坐标不能直接共用 | 每台设备独立 ROI；保存 camera/channel/frame/view revision/坐标单位，必要时建立跨视角目标关联 |
| 默认 initial_state=IN_REGION | 无新鲜初始证据也被认为安全 | 初始化必须经过新鲜、清晰观察；未完成前不可显示正常 |
| 仅检查“当前在区域外” | 开始时就在外面也可能被误报成“离开” | 区分位置条件与进入/离开事件；事件需要先确认前态，再确认后态 |
| 第 8–10 页连续帧和置信度窗口重置不完整 | 中间出现边界帧仍可能累计成“连续 3 帧”；已离开后还可能重复通知 | 按目标、设备、视角版本累计独立证据；中断清零；状态转换事件用唯一键去重 |
| 固定 N 帧没有时间限制 | 缓存重复帧、相隔很久的帧也可能成为证据 | frameId 去重、采集时间窗口、最大间隔、新鲜度校验，不能按轮询次数计数 |
| 置信度直接用 0.85 | VLM 自报分数、检测分数和跨视角关联分数并不等价 | 定义分数来源；先校验可见性与质量，再执行相应阈值；不可拿未标定分数包装可靠概率 |
| UNKNOWN 每帧都请求补证 | 两路反复请求，电池与带宽不可控 | UNKNOWN 进入时触发；冷却、超时、次数上限、失败原因；清晰主视角优先 |
| 图中包含“手动确认状态” | 用户点已处理可能被误用为视觉安全证据 | 人工反馈单独记；“已处理”触发复核，新的画面才能更新观察结果 |
| 默认前后帧与 5 秒录像 | SDK 未明确支持，当前也无完整持久化 | 由 capability 决定证据类型；证据文件独立保存，不能只引用会被清理的帧缓存 |
| 画面推断物体约 40cm 宽 | 未标定相机无法可靠得出实际尺寸 | 标为描述假设或不使用物理尺寸判定 |

## 当前代码实际进度

### 已有

- 原生 App 的五个标签、独立导航、AI 输入/回复、草案编辑与显式确认。
- DeepSeek Provider、带工具调用的多轮 loop、工具参数 Pydantic 校验。
- Run 持久化、顺序事件、请求 ID 去重、取消、并发和步数限制；重启把未完成请求标为 interrupted。
- 任务生命周期与告警状态分开；修改生成新草案，确认后替换旧任务。
- 双路 RTSP 模拟源与各任务独立区域、新鲜度/连续观察/冲突保留判断的最小 Worker。
- T8171/T8214 SDK 适配入口，未验证能力明确为 unknown。

### 尚未完成，不应当作已接通

- 当前 harness 是结构参考后的独立最小实现，未整体迁移 MiiMiao Runtime/RunManager/Scheduler。
- 没有统一 TaskEnvelope 工作负载队列、lease/checkpoint、执行中 steer、SSE 断点订阅；App 仍轮询。
- `target.box` 和 description 可编辑，但 Worker 实际只识别固定测试标记 17；尚未由圈选建立真实物体身份/特征。
- `minConfidence` 是配置字段，当前标记执行器未产出可校准置信度，不能宣称已做通用高置信视觉判定。
- 当前 worker 判断位置，不是完整的 IN→OUT / OUT→IN 转换引擎。
- 补证尚未按 UNKNOWN 入态调度；视角版本/相机移动不能仅凭已有 FrameRef 类型就算校验完成。
- 服务端证据记录引用实验室帧；实验室有缓存清理，必须补独立证据持久化。
- 真实设备、后台推送、连续录像、账号鉴权和正式公网部署均未验收。

## MiiMiao 对照与改造顺序

| MiiMiao v1.0 参考 | EvidenceGuard 用途 | 下一步 |
| --- | --- | --- |
| backend/kernel/agent_runtime.py | 稳定 execute/steer/cancel/shutdown 边界 | 分开会话编排与视觉任务执行，外层 API 不依赖模型细节 |
| backend/core/task_scheduler.py | TaskEnvelope + 有界队列 | 区分 chat、observation、supplementary；单 Skill 串行，补证请求有预算 |
| backend/store/run_event_repository.py | 每 run 单调事件序号与恢复 | 保存状态转换、工具回执和 checkpoint，恢复不能重复告警或启用 |
| backend/tools/registry.py | schema、handler、执行边界 | 工具生成草案；启用只能走用户确认；视觉判定引擎不执行任意自然语言 |

不搬入 MiiMiao 的办公、研究、计费等无关模块。本地 MiiMiao 仓库本轮只读，没有修改。

## 后续三个开发批次

1. **先补 Skill 的可执行合同和状态机。** 冻结目标身份、每视角 ROI、前态/后态、unknown 原因、执行能力与证据引用；用录像/帧序列验证连续性、边界、遮挡、重复帧、乱序、冲突、恢复。验收：不能从遮挡推导消失；持续任务报警后仍观察；复核不是立即恢复正常。
2. **紧接着接 MiiMiao 风格的调度与恢复。** 把上述 Skill 执行器挂到 TaskEnvelope 队列，补证单独调度；保存 checkpoint 和去重动作，App 展示结构化运行事件。验收：关闭 App 不停止服务端任务；服务重启可恢复且不重复通知；修改规则按版本生效。
3. **再替换感知与设备适配。** 从测试标记切到真实目标参考帧/跟踪与视觉分析；有正式 SDK 后逐台做握手、采集时间、唤醒/截图/码流/事件回执测试。验收：主视角遮挡→补充视角→证据记录→App 复核完整演示。

现在就进入这些基础建设，不以 UI 全面打磨为前置条件。以批次验收控制推进；比赛日期与成员投入尚未确认，因此不承诺具体日历工期。SDK 未到不阻塞前两个批次。

## 本轮验证

- 首页顶部按参考重新实现：纯背景、原生标题/副标题/铃铛、轻微倾斜标语、叠放状态卡、真实统计与同步时间。
- Xcode Simulator 构建通过；iPhone 17 Pro 模拟器视觉检查通过。
- 服务端 15 项测试通过，覆盖基础 Store、SDK 未接状态、无配置零模型调用、查询不创建任务、草案不自动启用、事件顺序、取消、重复请求与重启中断。
- 回归测试发现并修复工具分发参数 `name` 与草案名称 `name` 冲突。测试使用隔离数据库及脚本化 Provider，不代表真实摄像头或完整视觉执行链路已验收。
