# Skill、助手与摄像头联动 v0.3

## 本轮已接通

原生 App → 当前 Skill 的对话 → 模型工具调用 → 摄像头新图回执 → 图片分析/修改草案 → 用户确认 → 持续观察 → 状态变化与持久化证据。

### 任务对话

- 请求携带 conversationId、skillId、cameraId、requestId。服务端绑定任务上下文，不允许同一会话悄悄切换任务；请求 ID 去重也比较上下文。
- 从 Skill 详情进入后，只能选择本任务绑定的摄像头。助手工具查询、证据检索和复核自动限定当前任务；错误的任务/摄像头 ID 被拒绝。
- “请 AI 查看画面”先填入输入框，由用户发送。助手实际调用 request_camera_snapshot 后，消息中展示摄像头名称、采集时间、图片和失败原因。
- 对正在运行的任务提修改意见，只生成关联草案。继承原有区域和目标圈选；用户确认后才替换旧规则；旧任务已被替换或版本变化时拒绝过期草案。

### 摄像头调用

- 新 CameraService 统一能力检查、请求、8 秒超时和回执。
- fixture adapter 通过新图请求接口调用模拟器，等待请求之后采集的画面，不能直接把缓存帧当作新截图。
- 每次调用记录 camera_requested 与完成/失败事件。拿不到新图不修改任务结果。
- 捕获图片保存到服务端 SQLite media 表，App 和模型读取同一张有身份和时间的图片。任务证据另存媒体引用，源缓存清理后仍可读取；失败时显示无图记录。
- 单次助手视觉描述与持续守护引擎分开，聊天回复不直接写“已确认”或清除告警。

### Skill 状态机

- 区分生命周期、观察结果与告警处理状态。
- 进入/离开是状态转换，需要先观察到触发前的位置；启动时已在区域外不能当作“刚离开”。
- 按设备、帧 ID、采集时间和视角版本检查连续性；过期、重复、乱序和边界帧不能凑成连续证据。
- 两路证据冲突或补证过旧时进入 unknown。主视角不清晰时可使用时效合格的补充视角。
- 持续任务报警后继续运行；一次性任务命中后结束。同一告警 episode 不重复打开。
- “我已处理”仅标记已响应并请求复核。新的连续观察才能确认恢复。
- 确认启用时校验橙色目标框包含当前测试标记，并绑定参考帧与视角版本。

### MiiMiao harness 参考落地

参考冻结提交 fe43a78 的稳定 Runtime 边界、有界调度、工具注册和顺序运行事件，保持独立实现：

- TaskEnvelope + TaskScheduler 区分 chat / observation / camera 工作负载，分别限制并发。
- 请求入队有容量上限；对话可取消；摄像头请求有单独并发限制与超时。
- 每个 Skill 的 evaluation checkpoint 与业务状态/告警事件在同一 SQLite 事务内提交。
- 服务重启保留已确认位置和告警 episode，清除未完成的连续帧累计，等待启动之后的新帧。中断的聊天标记 interrupted，由用户重新发送。
- 主视角定期请求新图；UNKNOWN 补证有冷却和次数上限。暂停/停止后取消尚未结束的本地抓图任务。

当前是单进程有界调度，不是 Redis 队列或分布式 lease；尚未实现 MiiMiao 全套 steer、SSE 订阅和通用任务恢复。

## 实际验收

- Xcode Simulator 构建通过。
- 服务端 27 项测试、fixture-lab 29 项测试通过。
- 真实 DeepSeek 调用依次读取设备能力、请求 cam-a 新图、请求 cam-b 新图、生成草案；两路截图均返回 completed，未自动启用。
- 原生 App 中检查目标框、两路区域并确认启用。
- 真实 RTSP 合成场景验证：正常 → 移出 → 遮挡 → 已处理复核 → 仍在外部 → 回到区域内 → 主视角遮挡/补证。
- 上述流程保存了可读取的状态变化证据；告警只在一次真实状态转换中打开一次，恢复需要新证据。
- 重启服务端后任务恢复观察，历史图片可读取，未重复打开告警。
- 从原生 App 的 Skill 对话选择门铃补证视角，实际调用后显示对应图片、时间和模型回答。

## 当前边界

视觉执行器仍是带编号 17 的测试标记检测，通用箱子/宠物身份、真实多摄像头目标关联与 T8171/T8214 官方 SDK 尚未完成。minConfidence 是未来视觉执行器的预留字段，不把标记解码包装成已校准概率。当前无后台推送、5 秒录像与公网账号鉴权。

确认前的默认区域是待用户检查的初始框，不代表模型已经正确完成圈选。服务端会拒绝未圈住测试目标的启用请求。

## 新增接口

- `GET /api/media/{media_id}`：读取已保存的图片。
- `GET /api/skills/{skill_id}/events?after=N`：读取该任务顺序事件。
- 工具 `request_camera_snapshot(device_id?, purpose?)`：默认使用本次对话选择的摄像头；任务上下文自动限定设备范围。
- 实验室 `POST /api/cameras/snapshot` 与 `GET /api/cameras/requests/{id}`：仅模拟适配器使用，正式 SDK 在相同 CameraAdapter 合同内替换。

运行方法与服务配置见工程 README。
