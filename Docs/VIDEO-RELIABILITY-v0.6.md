# v0.6 历史录像：范围约束、可核验证据和重复评测

## 本轮改动

- 原生 AI 历史回顾增加时间范围弹层：按本次问题、全部日期、今天、昨天、过去 24 小时、自定义起止时间。取消不改变已选范围，应用只修改范围，不自动发消息。
- 选定范围随请求保存。服务端固定摄像头、任务和时间范围，模型工具参数不能扩大或缩小 App 手动指定的范围。今天/昨天按北京时间，跨轮次和重试不会偷换请求范围。
- 录像和离散图片检索共用手动时间约束，读取具体旧图片也检查范围；未知拍摄时间不会被当作今天，导入时间不冒充采集时间。
- App 消息旁显示该轮的摄像头和时间选择。服务端持久化筛选、向量检索、候选数量、逐段视频复核进度，App 显示实际阶段和已完成数量，不伪造百分比。
- 查询最终摘要由本轮工具回执生成；证据卡只对应本轮最后一次录像检索，不再让聊天模型从旧回答中编造可播放结果。卡片的视觉描述仍来自 Lite，保留“模型判断、请核验”标签。
- 区分没有可检索录像、模型未发现动作、画面无法确认和模型复核失败。错误不等于没发生，复核失败有独立状态。
- 播放默认从估计动作前 3 秒开始（不早于原片 0 秒），另有“跳到模型定位”按钮；保留原生返回。
- 沿用 MiiMiao 参考 harness；本轮只增强历史工具，不改变摄像头独占与实时 Skill 执行规则。T8171/T8214 SDK 端口继续预留。

## 重复评测结果

使用已有公开录像，4 个问题 × 3 次调用，共 12 次；温度 0。它们是开发回归样本，不是独立留出的准确率测试集。问题与人工粗标注见 [用例清单](../Cloud/evaluation/parcel-cases.json)，每次输出与耗时见 [原始评测结果](video-regression-v06.json)。标注答案、文件名和数据集标签不会放入模型请求。

| 用例 | 预期 | 3 次结果 |
| --- | --- | --- |
| 门廊原有长纸箱被拿走 | 匹配，约 4.5–5.5 秒 | 2 次匹配、均为 5 秒；1 次未取得有效结果 |
| 同一片段是否把包裹从车搬到门廊 | 不匹配，方向相反 | 3 次不匹配 |
| 立柱遮挡下能否直接看到放下 | 无法确认 | 3 次无法确认 |
| 身体遮挡下能否确认拿走原有包裹 | 无法确认 | 1 次无法确认；2 次未取得有效结果 |

9/12 次通过结构化判定检查，3/12 次未取得有效结果。最初运行只保留了 `ProviderError` 类型，不能据此断言是网络失败还是模型输出格式/时间校验失败；评测脚本已补充脱敏错误说明，供下次诊断。不能把失败排除后宣称“100% 准确”。

对 9 次有效输出逐条核对现有联系表，未发现上版“蓝色集装箱”那种明显场景混淆；仍有性别等非必要描述，因此不把摘要逐字正确性判为全面通过。有效的拿取定位只有两次，均为 5 秒，落在人工粗标注区间；这不能代表其他场景定位误差。

12 次复核请求耗时中位数约 12.73 秒、最慢约 48.96 秒（包括请求内部的格式重试，不包括排队时间）。应继续优化稳定性与延迟，当前不适合宣称实时告警可靠。

额外一次文本到视频的向量检索在 3 个原始视频中把正确的 t4 排第一，得分约 0.460，其次 d1 0.376、o1 0.320。这里只检查完整视频的排序；生产查询仍使用 v0.5 的 20 秒分段、5 秒重叠。不能把这一条排名结果当作大库召回率。

**当前结论：历史检索可继续开发和演示，自动守护的模型可靠性尚未验收。** 上版明显幻觉记录仍保留，不用这轮的小样本结果覆盖失败历史。

## 复测命令

从 Cloud 目录运行（私有配置留在工程外）：

```bash
EG_ENV_FILE=/私有路径/evidenceguard.env PYTHONPATH=server \
.venv/bin/python -m evidenceguard.video.evaluate \
  --manifest evaluation/parcel-cases.json \
  --video-root /本地测试录像目录 \
  --output /评测结果路径/result.json --repeats 3
```

测试视频不随工程打包，使用来源为 [公开数据集](https://huggingface.co/datasets/DiricziZsolt/Latch-Video-Package-Theft) 的 t4.mp4、d1.mp4、o1.mp4。尚未见数据卡声明明确授权，外部发布演示素材前需另核查许可。若样例文件缺失，报告标为 missing，不冒充通过。

自动评测分别记录结构化判定、假确认、漏掉正例、时间点到人工区间的距离、响应耗时及失败。自然语言描述真实性、遮挡标注和动作先后仍需人工审核；脚本不会自动批准模型用于守护。

## 尚缺的公开素材与后续补拍

用户当前没有实拍视频，本轮继续用公开样片；下列覆盖项仍明确待验证：

1. 同一段未拼接录像完整记录放下 → 静置 → 拿走，动作全程可见。
2. 有人经过但不碰包裹；有人只在关注区域内移动包裹，不拿走。
3. 夜间、逆光、遮挡、多人，以及两台目标摄像头的真实视角。
4. 对动作开始和结束人工逐帧标注，并由团队第二人复核。

可按每段 30–90 秒准备：固定机位，空场景 5 秒；放下包裹；等待 10 秒；按正例或反例操作；保留结尾 5 秒。记录摄像头、实际开始时间、操作内容、手工动作区间。公共视频若缺这段连续过程，就继续列缺口，不拼接成“全流程通过”。

## 工程检查

本轮 58 项服务端测试通过，Xcode iPhone Simulator 编译通过。新增覆盖 App 范围压过模型参数、日期边界、查询请求幂等范围、复核进度、失败与遮挡分离、空结果不编造旧卡片、评测指标判定。

随后完成原生端全流程：编辑框填入查询 → 手动选择全部日期 → 点击发送 → 回传 3 段候选及复核结果 → 点击 A 的卡片播放。首屏显示拿取前的画面，点击“跳到模型定位 00:05”显示拿起长纸箱带走的画面；两个播放入口分别生效。该轮返回一段匹配、一段不匹配、一段无法确认，见 [原生查询回执和进度](native-history-v06.json)。服务异常结果可通过“复核未完成，编辑后重试”恢复本轮消息及手动范围后再次发送。
