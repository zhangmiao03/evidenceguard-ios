anker 早晚报告与 Agent 验收（2026-10-15）

本轮交付
早晚报告可分别订阅、设置整点时间，使用用户时区；新设置默认早安 08:00、晚间 20:00，均需用户开启。报告保存到 anker 主会话和消息记录，iOS 推送仍服从系统授权、用户开关、免打扰、过期、前台呈现与点击回执。没有自动给既有用户开启新订阅。

旧客户端兼容
已开启的旧每日概况迁移为原时间的一份晚间报告，不增加早报。旧客户端关闭每日概况会关闭两个订阅，其他旧字段更新保留现有早报。新 iOS/Web 识别旧服务，继续发送旧字段，避免团队/审核服务的严格 schema 拒绝新字段。新界面只在新客户端可见；旧 build 10 仍显示原单次概况设置。没有新 TestFlight 上传或分发。

调度与提醒
按本地日期、早/晚 slot 去重，适配跨时区和 DST，停机恢复只补最近未过期的一份；修改时间不重复生成当天同一 slot。旧 daily 触发取消，避免新旧同发。早晚报告属于用户主动订阅，不用普通主动提醒价值评分过滤，也不占每日 6 条普通提醒配额；普通提醒原频率、免打扰不变。

证据与模型职责
确定性部分计算区间、设备事件数量、设备检测标签、保存的画面取样、缺记录设备和当前未确认任务。排除合成来源与回放，事件时间采用设备事件时间，并限制接收时间。不把最后一条记录当在线心跳；没有新事件不等于设备离线，也不等于家里安全。当前缺少连续覆盖证明，因此报告必须保留这一说明。
豆包通过正式 Codex App Server 读取只读来源，选择先展示的任务；实际正文由事实模板生成。模型不能改设备、扩大采集或设置通知；模型失败时仍生成明确说明缺口的事实报告。设备/任务名称是非可信文本，长或含标点的名称不直接拼入助手正文。
新增 read_home_report 是只读预览工具，可以聊天查询过去 24 小时报告，不开启订阅、不新取图、不发推送。

本轮真实测试修复
1. 首轮选取的英文历史题未召回：记忆提取请求超过原 25 秒外层时限，进入重试。改用同一豆包模型的记忆专用 JSON 输出，关闭此提取请求的深度思考，外层时限 65 秒以覆盖底层 60 秒请求时限。正常聊天/工具请求未改为此模式；没有更换模型或增加备用提供商。来源原话、纠正、删除抑制和隐私验证保留。
2. 首轮“仓鼠名未知”的回答正确，但自动判定漏掉“没告诉过我”，修正判定并保留原结果，不将该项算成模型幻觉。
3. 报告模板曾把恶意测试设备名原样带入正文，现限制显示名称；原始来源仍可检查。
4. 人工检查发现“接上摄像头就能守夜”的措辞会夸大后台能力。补充前台采集、APNs 与事件上传的区别，以及尚无房主身份录入功能；4 道真实追问题通过。

尚需真实验收
摄像头硬件/凭证、不依赖手机前台的事件上传链路、真实事件视觉分析、锁屏 APNs 展示与点击回到证据页。以上自动化/模拟器结果不替代这些测试。APNs accepted 也不是手机已展示。现阶段不能承诺全天候守护或“家里安全”。
记忆仍是异步选择性提取，聊天记录不是每字都写成长记忆；失败有持久重试和可见状态，不承诺每轮实时完成。

复现入口
Cloud/evals/personal_agent_acceptance.py --run-real --work-dir <隔离目录> --output <结果.json> [--hf-evidence-cases <资料.json>] [--only-hf]
需正式服务同等模型/Codex环境，但脚本强制隔离 SQLite、关闭 APNs 和 worker，不继承设备账号。不要使用真实用户输入作为公开测试数据。HF 输入格式为 {"cases":[{"id":"...","evidence":["原始用户证据"],"question":"...","expectedSubstrings":["可接受回答"]}]}。判定器为轻量断言，重要结果应人工复核，不代表完整语义评分。
输入、模型原始结果、首轮失败记录、部署备份保存在私有工作目录，不含在仓库或公共附件中。
