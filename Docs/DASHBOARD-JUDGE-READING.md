# Dashboard 评委阅读路线（2026-10-16）

本次仅重新组织公开 HTML Dashboard 的监控界面与只读投影。作品演示的手机页面、原生 iOS、业务 API、硬件控制与 App 鉴权保持原实现。网站公开查看，无需登录。

## 推荐阅读顺序

1. **运行总览**：产品三层结构、已记录任务需求、调用数量、最终交付。可以选择一条已有任务阅读；页面不触发新的 Agent 调用。
2. **Agent 与模型**：可点击的 Agent Loop 结构图；选择实际任务后，节点显示相关回执数量，下方依时间逐步回放。模型 HTTP、Codex 执行器往返和工具执行分别计数。
3. **对话与 Trace**：任务选择器、步骤列表、上一步 / 下一步、当前步骤说明、完整正文与最终回复。原始接口轮询移入“开发者记录”。
4. **图片分析 / 视频向量库**：沿来源图→上传副本→模型理解，以及入库→向量索引→候选→视频复核阅读真实素材、结果与限制。
5. **质量与试跑**：完成回执、未知结果、失败状态和未采集的最终正文分开；不计算没有人工标注依据的准确率。

可直接分享环境链接：

- 总览：`/dashboard?view=overview&environment=demo`
- 检索任务 Loop：`/dashboard?view=agent&environment=review`
- 检索效果：`/dashboard?view=vectors&environment=review`
- 来源图片：`/dashboard?view=images&environment=demo`

参数只选择采集环境，不授予 App 业务权限。导航保留环境；切换环境清空旧筛选与数据。公开媒体只能通过既有同源只读清单访问。

## 数据口径与诚实展示

- 任务列表只从真实 `model` 或 Agent/context 事件建立，不把 HTTP 轮询凑成任务数。资源快照不会变成历史执行。
- 同一记录 ID 去重。只有 `agent.result` 的实际正文计入“留有最终回复”。`http_ok` 不能推导 Agent 完成。
- “明确保留无法确认”通过最终回复中的无法确认等文字识别，是阅读辅助，不是经标注的质量评分。
- 筛选决定可选择哪些任务；展开一条任务时恢复同一 Trace 的已保留上下文，页面明确说明包含筛选外记录。
- Loop 是实现职责示意；节点相关回执可以重叠，不是六个独立 Agent，也不保证每次任务都调用一个独立核验模型。实际循环次数看步骤回放。
- 模型原始输出与运行时最终回复保留差异。图片副本按记录来源展示；合成测试素材保留来源，不冒充摄像头拍摄。
- Codex 执行器内置提示词、底层 HTTP 与模型内部推理不可见。已采集的主程序指令和返回可读；加密推理字段也被省略。密钥继续在写库与公开投影时过滤。
- 最近 3,000 条快照之外，额外补取最近 20 组 Agent / 模型 / 视觉任务（最多 240 条、2.5 MB）；继续受总快照 6 MB 限制。过大的单条记录会跳过并明确截断，避免它遮蔽后续较小回执。原数据库保留上限未改变，已被淘汰的数据不能恢复。
- 长 ID 仅在阅读摘要中替换为“记录编号”，原文与关联键不修改；详情和 JSON 导出仍可核对真实标识。
- 所有硬件控制在手机 App 的官方 SDK 执行，Dashboard 不提供配网、云台、对讲控制。

## 验证

本地生产构建通过，20 项 Web 单元测试、29 项 Python 监控测试通过；48 项 Chromium / Firefox / 桌面 WebKit / 手机 WebKit 浏览器检查通过（首次 44 项，修正模态框选择器后补跑剩余 4 项）。覆盖 14 个监控页面、任务顺序、未确定结果、正文与密钥隐藏、环境链接、移动端无整页横向溢出及作品演示零业务写请求。

内置浏览器使用真实 review 环境导出的快照复核循环图与任务回放。真实模型调用发生于快照记录时间，本次 UI 检查没有伪造调用或把回放说成刚完成的新任务。上线后的来源与版本检查追加在 [比赛网站发布记录](COMPETITION-WEBSITE.md)。
